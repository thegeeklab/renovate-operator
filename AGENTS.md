## Critical Rules

1. **ALWAYS use `make` targets** for build/test/lint/generate/dependency operations. Never run `go build`, `go test`, `npm install`, `npx`, `eslint`, `tsc` directly. If no make target exists, add one first.
2. **Never run `make test-e2e`** without explicit user instruction.
3. **After editing `api/v1beta1/*_types.go`**: run `make generate` then `make manifests`.
4. **After editing `*.templ` files**: run `make templ`.
5. **Never edit generated files**: `zz_generated.deepcopy.go`, `*_templ.go`, `icons.templ`, `mock_*.go`, `config/crd/bases/*.yaml`, `config/rbac/*.yaml`, `config/webhook/manifests.yaml`.

## Build/Test/Lint

### Development

- `make build` — full build (manifests + generate + fmt + vet + frontend + go)
- `make run` — run locally (mirrord + air hot reload)
- `FRONTEND_DEV=true make run` — run with Vite dev server
- `make build-go` — Go binaries only
- `make frontend-build` — frontend assets only
- `make docker-build IMG=docker.io/thegeeklab/renovate-operator:latest` — container image

### Testing

- `make test` — all unit tests (envtest, excludes e2e)
- `make test FOCUS="TestName"` — single test
- `make test SKIP="TestName"` — skip test
- `make helm-test` — Helm unit tests
- `go test -race ./...` — race detector (only non-envtest packages)

Framework: Ginkgo v2 + Gomega + testify. Runner: gotestsum. Fixtures in `fixtures/` subdirectories. Mocks generated by mockery via `make generate`. Do not run `go test` on envtest packages directly.

### Linting

- `make lint` — all (yamlfmt-dry, golangci-lint, eslint, typecheck, cspell)
- `make golangci-lint` — Go only
- `make eslint` — frontend only
- `make typecheck` — TypeScript
- `make yamlfmt-lint` — YAML format
- `make cspell` — spell check

### Code Generation

- `make generate` — all (deepcopy, mocks, icons, templ, yamlfmt)
- `make manifests` — CRDs/RBAC/webhooks
- `make templ` — templ only
- `make gen-icons` — icons only
- `make fmt` — Go format (gofumpt -extra)
- `make yamlfmt` — YAML format

### Dependencies

- `go get -u ./...` — update all Go deps
- `go mod tidy` — tidy Go modules
- `npm update` — update npm deps
- `make frontend-deps` — install frontend deps

## Code Style

### General

- **Follow existing patterns** in the codebase
- **Do not rename pre-existing variables** — only rename for genuine clarity improvements
- **Prefer inline code** over new abstractions unless pattern is established
- **Keep lines short** — `lll` linter is enabled

### Imports

Standard library → blank line → third-party → blank line → local packages.

```go
import (
    "context"
    "fmt"

    "k8s.io/apimachinery/pkg/runtime"
    "sigs.k8s.io/controller-runtime/pkg/client"

    "github.com/thegeeklab/renovate-operator/api/v1beta1"
)
```

### Naming

- Exported: PascalCase (`Renovator`, `GitRepo`, `NewReconciler`)
- Unexported: camelCase (`defaultSchedule`, `getRepositories`)
- Acronyms: uppercase for exported (`API`, `URL`), lowercase for unexported (`api`, `url`)
- CRD types: match Kubernetes naming
- Interfaces: name after what they do (`Provider`, `Scheduler`)

### Error Handling

- Always check errors, never ignore
- Wrap with `fmt.Errorf("context: %w", err)`
- No `errors.New` with dynamic messages (`err113` linter)
- Log with context before returning

```go
if err := r.Client.Get(ctx, key, obj); err != nil {
    return fmt.Errorf("failed to get resource: %w", err)
}
```

### Logging

- Use `log.FromContext(ctx)` (controller-runtime logger)
- `log.Info("reconciling renovator", "name", req.NamespacedName)`
- `log.Error(err, "reconcile failed", "name", req.NamespacedName)`
- Inject `logr.Logger` via dependency injection

### Comments

- Document all exports: `// Reconciler reconciles a Renovator object.`
- Use `//` only
- No unnecessary comments

### Interface Implementation

```go
type GitHubProvider struct {
    client *github.Client
}

var _ provider.Provider = (*GitHubProvider)(nil)
```

### YAML Struct Tags

Must be kebab-case (enforced by `tagliatelle`):

```go
type RenovatorSpec struct {
    Schedule       string         `yaml:"schedule"`
    PlatformConfig PlatformConfig `yaml:"platform-config"`
}
```

## Frontend

### Templ Syntax

- Components: `templ ComponentName(params) { <html>content</html> }`
- Expressions: `{ variable }`, `{ function() }`
- Composition: `@ComponentName(args)`
- All tags must be closed: `<div></div>` or `<br/>`
- Edit only `*.templ` files, never `*_templ.go`

### HTMX Patterns

- Requests: `hx-get`, `hx-post`, `hx-put`, `hx-delete`
- Triggers: `hx-trigger="click"` (default), `"change"`, `"keyup delay:500ms"`
- Targets: `hx-target="#result"`, `"closest tr"`, `"next .error"`
- Swapping: `hx-swap="innerHTML"` (default), `"outerHTML"`, `"afterend"`
- SSE: `hx-ext="sse"` with `sse-connect="/events"` and `sse-swap="message"`
- Loading: add `class="htmx-indicator"`

### Tailwind CSS (v4 via `@tailwindcss/vite`)

- Utility-first, no inline styles
- Responsive: `sm:text-left`, `md:flex`, `lg:grid-cols-3`
- States: `hover:bg-blue-700`, `focus:ring-2`, `disabled:opacity-50`
- Spacing: `p-4`, `m-2`, `gap-6`
- Layout: `flex items-center justify-between`, `grid grid-cols-2 gap-4`

## Architecture

- **Operator pattern**: kubebuilder + controller-runtime reconcilers
- **API types**: `api/v1beta1/` with kubebuilder markers
- **Reconcilers**: `internal/controller/`, use `pkg/util/reconciler` helpers
- **Provider abstraction**: `internal/provider/` with `github/`, `gitea/` subpackages
- **Webhook receivers**: `internal/receiver/` with per-platform subpackages
- **Frontend**: served by manager on port 8082, Vite-bundled static assets
- **Context**: always pass `context.Context` first parameter; `noctx` linter enforced
- **K8s helpers**: `pkg/util/k8s/` for naming/metadata, `pkg/util/` for general

### Creating New CRDs

Use kubebuilder scaffolding only. Do not manually create API types or controllers.

```bash
# With controller (default)
kubebuilder create api --group renovate --version v1beta1 --kind <KindName>

# Without controller
kubebuilder create api --group renovate --version v1beta1 --kind <KindName> --controller=false

# Add webhooks
kubebuilder create webhook --group renovate --version v1beta1 --kind <KindName> --defaulting --validation
```

After creating: edit types → `make generate` → `make manifests` → implement reconciler.

Project config: domain `thegeeklab.de`, group `renovate`, version `v1beta1`, layout `go.kubebuilder.io/v4`.

## Testing

**Always write tests alongside implementation. TDD is mandatory.**

### TDD Process (Red-Green-Refactor)

All new features and bug fixes **must** follow strict TDD:

1. **Red** — Write a failing test that describes the desired behavior. Run it and confirm it fails (`make test FOCUS="TestName"`).
2. **Green** — Write the minimum production code required to make the test pass. Run it and confirm it passes.
3. **Refactor** — Clean up code while keeping tests green. Run `make lint`.

Do not write production code before its test. Do not write multiple tests before making them pass one at a time. If a test cannot be written first, the design needs rethinking.

### Process

1. Write test first — copy `BeforeEach` from nearest sibling `*_test.go`
2. Run test to confirm failure (red)
3. Implement production code
4. Run test to confirm pass (green)
5. Run `make lint`

### Test Tiers

| Tier                   | Tool                               | Use for                                        |
| ---------------------- | ---------------------------------- | ---------------------------------------------- |
| Component unit         | `fake.NewClientBuilder()` + Ginkgo | Reconciler logic, status updates, job creation |
| Controller integration | envtest (via `make test`)          | Full reconciliation loops, webhook interaction |
| E2E                    | Kind cluster                       | **Do not run** — not yet implemented           |

Component unit tests preferred for `internal/component/`. Only use envtest when controller predicate integration must be verified.

### Coverage

- Test all condition transitions (running/not-running, completed, failed)
- Test error paths from dependencies
- Test edge cases: concurrent jobs, missing resources, label truncation, nil pointers
- Do not test trivial getters/setters, generated code, or K8s client behavior

### Patterns

- Copy `BeforeEach` from existing test in same package
- Use `DiscoveryLabels()` / `RunnerLabels()` helpers (not hand-crafted maps)
- Use `GetCondition()` for assertions (check `Status`, `Reason`, nil checks)
- Use `metav1.Now()` for job timestamps (deterministic ordering)

## Common Pitfalls

- **Stale generated files**: run `make generate` after changing API types
- **Editing generated templ files**: edit `.templ` source, not `*_templ.go`
- **envtest failures**: run `make setup-envtest` if envtest fails
- **E2E tests**: require Kind cluster — never run autonomously
- **mirrord**: `make run` uses mirrord; ensure `mirrord.json` is configured
- **Line length**: `lll` linter enabled — keep lines short
- **YAML tags**: must be kebab-case (`tagliatelle`)
- **Defaulting webhooks**: when adding pointer fields (`*bool`, `*int32`) to API types, update defaulting webhook in `internal/webhook/v1beta1/`
